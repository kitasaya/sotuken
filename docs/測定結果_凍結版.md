## 9. 旧値との差分

| 指標 | 旧記録 | 凍結値 | 原因 |
|---|---|---|---|
| R2一方通行検出 | 旧ノード距離方式16way・18点 | 現行方式10 unique way・12点（A4/B4/C4） | **ロジック変更**。最近傍ノードから有限線分距離へ変更し、判定点・rank1が変化。8/24 liveタグと8/1 attic固定タグの差は0で、スナップショット差ではない |
| R1の`system_violation_count=11` | 初期ルートのoneway 1 + two-step 10 | 提示R1は15/15ペア測定・oneway 0件 | **集計対象と不具合修正**。旧oneway 1は閉ループ偽陽性、two-step 10はLayer 2で経路除外対象外 |
| 距離指標 | 外部ルート距離との対比を検討 | 本システム内部の制約なしルートと法規準拠ルート | **測定定義の確定**。同一エンジン・同一OD・同一設定で法規制約の有無だけを変え、外部サービスとの距離対比は採用しない |
| タグ空間内網羅性 | exempt 15 / forward 238 / detected 1 / unknown 0 | exempt 15 / forward 239 / detected 0 / unresolved 0 | way 28413951を偽陽性から順走へ訂正。タグ空間外を含む再現率とは呼ばない |
| 真偽確認方法 | 独立真値表による精度評価を計画 | 全検出点のストリートビュー確認 | **評価方針の確定**。Precision・Recall・F1は測定対象から除外 |
| 曖昧性3段階 | 188/379、150/379、12/379 | 同じ | 固定PBF再走査で再現。スナップショット差なし |
| 現行12点の判定不能 | 1.5m:0、2.0m:3、2.5m:4 | 同じ | 固定入力で再現 |
| R2全検出ゼロペア | 5/15 | 5/15 | 固定入力で再現 |
| R1提示ルート | 14/15測定・1ペア未測定 | **15/15測定・oneway 0件** | 閉ループ修正後に全ペアを固定PBFで再採点 |

最も重要な変更は、way 28413951を閉ループ偽陽性と確定して+419.9mを撤回したこと、および標準bikeとのA/B比較で除外機構の寄与を確認できなかったことである。R2の現行12点と、全検出点をストリートビュー確認する評価方針は変わらない。

1. `measurement-freeze-2`をcheckoutする。
2. PBFのSHA-256、GraphHopper 11.0、image digest、`datareader.data.date`を照合する。
3. GraphHopperを起動し、`smoke_test_trim_geometry.py`を実行する。
4. `remeasure_batch21_r2.py`でR2全379点を再採点する。
5. `measure_batch21_exclusion.py`で15ペアの条件A/Bとタグ付きoneway通過254件を再測定する。
6. `freeze_measurements.py`で`measurement_freeze_20260830.csv`とOD表を生成する。
7. 12点のA/B/C各4点、R1 15/15違反0、条件A/B差0、説明不能未検出0/254、リンク切れを検算する。
