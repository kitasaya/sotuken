#### 1-1-g. 出力の照合結果：**内容は完全一致**（差分は改行コードのみ）

`diff` は全行を差分として報告するが、原因は行末である。

| ファイル | 既存（作業ツリー） | 再生成 | バイト数 |
|---|---|---|---|
| `measurement_freeze_20260830.csv` | LF × 82行 | CRLF × 82行 | 13,289 → 13,371（+82） |
| `measurement_freeze_od_20260830.csv` | LF × 16行 | CRLF × 16行 | 2,035 → 2,051（+16） |

行末を正規化すると完全一致する。

```
$ diff <(tr -d '\r' < data/measurement_freeze_20260830.csv)    <(tr -d '\r' < <再生成>)
（差分なし）
$ diff <(tr -d '\r' < data/measurement_freeze_od_20260830.csv) <(tr -d '\r' < <再生成>)
（差分なし）
```

**原因：** Python の `csv.DictWriter` は CSV 仕様どおり行終端に `\r\n` を書く。
一方 `.gitattributes:2` が `* text=auto eol=lf` を指定しているため、
コミット時とチェックアウト時に LF へ正規化される。

```
$ git check-attr -a bicycle-navi/backend/data/measurement_freeze_20260830.csv
... text: auto
... eol: lf
$ git cat-file -p HEAD:bicycle-navi/backend/data/measurement_freeze_20260830.csv | grep -c $'\r'
0
```

git の正規化フィルタを適用した blob SHA が、コミット済み blob と一致することも確認した。

```
$ git hash-object --path bicycle-navi/backend/data/measurement_freeze_20260830.csv <再生成>
c214fc3feb4fc54440013d9c93e1161480498e7d
$ git rev-parse HEAD:bicycle-navi/backend/data/measurement_freeze_20260830.csv
c214fc3feb4fc54440013d9c93e1161480498e7d   ← 一致

$ git hash-object --path bicycle-navi/backend/data/measurement_freeze_od_20260830.csv <再生成>
2c84a25f173535f7d6c0ab298e558756500de9ce
$ git rev-parse HEAD:bicycle-navi/backend/data/measurement_freeze_od_20260830.csv
2c84a25f173535f7d6c0ab298e558756500de9ce   ← 一致
```

**結論：`freeze_measurements.py` は現環境で完走し、凍結CSV 2件を bit 単位で再現する。**
実際に上書き実行してコミットした場合も、git の正規化により**差分0行**になる。
改行コードの差はデータの不一致ではなく、`.gitattributes` の正規化に由来する表示上の差であり、
**調査・修正の対象ではない。**

### 1-6.〔問題なし〕docs のハッシュ記録は CRLF/LF 差の影響を受けない

§1-1-g で CSV の再生成物が CRLF、作業ツリーが LF になることが分かったため、
**バイト単位のハッシュを記録している箇所が影響を受けないか**を点検した。

```
$ rg -i 'sha256|sha-256|md5|ハッシュ|hash' docs/
```

ヒットしたハッシュ記録は5件で、内訳は次のとおり。

| 記録箇所 | 対象 | 種別 | EOL正規化の影響 |
|---|---|---|---|
| `docs/測定仕様_凍結版.md:23` | `kanto-260801.osm.pbf` | バイナリ・`.gitignore` の `*.pbf` で除外 | **なし** |
| `docs/測定仕様_凍結版.md` | GraphHopper イメージ digest | Docker イメージ（ファイルではない） | **なし** |
| `docs/測定仕様_凍結版.md:39` | **`bicycle-navi/backend/data/google_routes_input.csv`** | **tracked な CSV** | **要確認** |
| `docs/文献/精読ノート/精読ノート_Whiteほか2000.md` | 文献PDF | `.gitignore` の `*.pdf` + `.gitattributes` の `*.pdf binary` | **なし** |
| `docs/文献/精読ノート/精読ノート_縄野間邊2021.md` | 文献PDF | 同上 | **なし** |

**唯一の tracked CSV（`google_routes_input.csv`）を実測照合した結果、記録値と一致する。**

```
実測   = b79a2ded191dabcdca73119035c0e1550d3b06bcc246cfdf756a174c3d270d30
記録値 = b79a2ded191dabcdca73119035c0e1550d3b06bcc246cfdf756a174c3d270d30   ← 一致
CRLF行数=0 / 総行数=16 / bytes=2,140   ← 作業ツリーは LF
```

記録値は LF 版のハッシュである。`.gitattributes:2` の `* text=auto eol=lf` は
プラットフォームを問わずチェックアウト時に LF を強制する（`core.autocrlf` より優先される）ため、
**どの環境で clone しても同じ値になる。**

**凍結CSV（`measurement_freeze_*.csv`）についてはハッシュ記録が存在しない。**
したがって §1-1-g の CRLF/LF 差が既存の記録値と衝突することはない。

> **ただし1点だけ注意が要る。** 参考値として CRLF 版のハッシュを計算すると
> `47138ef4ad97336d8e21d5892b3ee19a5ac9e5581bd43e1d0c77ab547ea56777` となり、
> 記録値と異なる。`google_routes_input.csv` を Python の `csv` モジュールで
> 書き出し直すと作業ツリー上は一時的に CRLF になり、**コミット前に
> `shasum` を取ると記録値と食い違う。** 照合するときは
> `git show HEAD:<path> | shasum -a 256` を使うか、コミット後に確認すること。
> 今後ハッシュを記録する際は、**LF 正規化後の値である旨を併記する**のが安全である。
