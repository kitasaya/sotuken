## 結論

`get_bulk_way_data`の「垂直距離」は、**無限直線への垂線距離ではなく、有限線分へのユークリッド最小距離**である。wayが複数セグメントを持つ場合は全セグメントの最小値を採用する。座標は緯度経度の度数をそのまま等方的に扱わず、判定点緯度における`cos(lat)`を用いて経度方向をメートル換算する。`match_margin_m`は、異なるway IDへ重複除去した後の1位・2位候補の距離差である。第2候補が正解wayとは限らないため、この差を対応正解確率や信頼度と解釈しない。

したがって、指示書で懸念された「way端点の外側でも無限直線への距離を返す」「日本の緯度で経度方向が約0.82倍になることを無視する」という2つの問題は、現行コードにはない。

## 2. 有限線分か無限直線か

### 該当コード（387–390行）

```python
t = -(ax * dx + ay * dy) / seg_len_sq
t = max(0.0, min(1.0, t))
return math.hypot(ax + t * dx, ay + t * dy)
```

判定点を原点とし、線分`a-b`上の射影位置をパラメータ`t`で求めている。その後`t`を`[0,1]`にクランプしている。

- `0 <= t <= 1`：垂線の足が線分内部にあり、垂線距離を返す。
- `t < 0`：`t=0`となり端点`a`までの距離を返す。
- `t > 1`：`t=1`となり端点`b`までの距離を返す。
- 退化線分（`a == b`）：384–385行で端点距離を返す。

**判定：有限線分への最小距離。** Bernstein & Kornhauser (1996)のpoint-to-curve定義と整合する。端点付近で無限直線を誤選択するという指示書の懸念は該当しない。

## 3. 複数セグメントwayの扱い

### 該当コード（403–406行）

```python
return min(
    _point_to_segment_dist_m(lat, lng, geometry[i], geometry[i + 1])
    for i in range(len(geometry) - 1)
)
```

geometryの隣接ノード対すべてについて線分距離を計算し、**全セグメントの最小値**をway距離とする。代表セグメントだけを使う実装ではない。geometryが1点なら点距離、0点なら`inf`として候補から除外する（399–405行）。

## 4. 候補順位と`match_margin_m`

`_rank_way_candidates`は各wayのgeometry距離を計算し、way IDで重複除去した上で距離昇順に並べる（424–444行）。同一wayがUnionクエリ結果に複数回入っても、2位候補に同一wayが入りマージン0となることを防いでいる。

### 該当コード（505–507行）

```python
rank1_dist, rank1_elem = ranked[0]
margin = (ranked[1][0] - rank1_dist) if len(ranked) >= 2 else None
ambiguous = margin is not None and margin < MATCH_AMBIGUOUS_MARGIN_M
```

したがって、

- `match_dist_m`：1位wayまでの距離
- `match_margin_m`：**2位距離 − 1位距離**
- `match_ambiguous`：候補が2本以上あり、マージンが2.0m未満
- 候補0本または1本：`match_margin_m=None`、`match_ambiguous=False`

である。2.0mの根拠はコードコメント19–22行にあり、想定外の判定変化4地点が0.50–1.74m、正常10地点が2.75m以上だったという本研究データの分離に基づく。文献由来の閾値ではない。

## 5. 座標系と距離の歪み

### 該当コード（30–32、376–380行）

```python
_M_PER_DEG_LAT = 110_540.0
_M_PER_DEG_LNG_EQUATOR = 111_320.0
kx = _M_PER_DEG_LNG_EQUATOR * math.cos(math.radians(lat))
ky = _M_PER_DEG_LAT
```

緯度差・経度差を局所平面のメートル座標へ変換している。経度方向は判定点緯度の`cos(lat)`で補正されるため、日本の緯度約35度で1度経度が赤道の約0.82倍になることを反映している。

これは測地線を厳密に計算する投影座標系ではなく局所平面近似だが、候補取得半径の既定値が20m（447、476行）である用途では設計上整合的である。既存smoke testは大円距離のブルートフォース実装との相対差1%未満を検査するケースを持つ（283–312行）。

## 7. 論文に書ける記述

> 判定点とOSM wayとの距離は、判定点近傍を局所平面へ換算した上で、wayを構成する各有限線分への最小ユークリッド距離として算出した。線分上への射影が線分外に位置する場合は最寄り端点までの距離を用い、複数線分からなるwayでは全線分の最小値を採用した。また、最近傍候補と第2候補の距離差をマッチングマージンと定義し、実測上不安定な判定が集中した2m未満を判定不能として区別した。

## 8. 修正要否

**この確認事項に関するコード修正は不要。**

ただし論文中の用語は、単なる「垂直距離」よりも「有限線分への最小距離」と書く方が数学的に正確である。また、Quddus et al. (2007)が指摘する近接道路での一般的不安定性は残る。旧B群7事例は現行方式で5事例が非検出となり、2事例が残存した。この変化はpoint-to-curve一般の保証ではなく、本研究データでの実測に限定する。
