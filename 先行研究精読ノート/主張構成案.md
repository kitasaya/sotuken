# 主張構成案

**作成日：2026-08-26 ／ 方針：旧18点の診断と現行12点の再測定を役割分離する**

## 0. 論文全体を貫く一文

本研究は、道路交通法8条1項に反する一方通行逆進入を経路生成段階で排除する自転車ナビゲーションを実装し、外部ルートの旧方式による18検出点を全数監査した。その結果、真の違反は2事例・3点に限られ、残りからOSMタグ不備、道路way対応の誤り、候補僅差という3つの系統的限界を同定した。有限線分距離へ修正後もB群2事例が残り、固定PBFでの現行出力は一方通行12点・二段階右折2点だったため、距離指標の改善だけでは法的判定の正しさを保証できないことを示した。

「Google Mapsに違反が多い」ではなく、**異種経路データをOSMへ対応付け、タグから法的結論を出す際の測定限界を、現地監査と再測定で明らかにした**ことを中心貢献とする。

## 1. 推奨章立て

### 第1章　背景と研究課題

1. 2026年4月1日から16歳以上の自転車運転者に交通反則通告制度が適用された。
2. 一方通行規制への逆進入は通行禁止違反（8条1項、反則金6,000円）である。
3. 死亡・重傷事故の法令違反割合は背景事実として示すが、ルート回避の効果へ直接接続しない。
4. Layer 1の主根拠は法的リスクであり、安全性は条件依存の補助根拠とする。

### 第2章　先行研究と本研究の位置づけ

1. 縄野・間邊(2021)を直接先行研究の主引用とする。左側通行を重み∞で事前排除するため、「事前排除」は同研究との差別化ではない。
2. 差別化は、一方通行・二段階右折という対象、OSMに基づく実装、外部サービス比較、全数現地監査、測定限界の定量化に置く。
3. Quddusの4群分類を上位に、古典的geometric方式の3方式を下位に置く。
4. 本研究はtrajectory map matchingそのものではなく、cross-dataset road-network matching / conflationに近い。ただし完全なnetwork-to-network conflationではない。

### 第3章　システム設計と再現可能な実験条件

1. 三層構造を示す。Layer 1は経路除外、Layer 2は案内、Layer 3は推奨情報である。
2. 外部ルート採点だけが座標からOSM wayを推定するため、本システム経路より不確実であることを先に明示する。
3. GraphHopper 11.0、`2026-08-01T20:21:21Z` PBF、SHA-256、同日時のOverpass atticを記録する。
4. 最近傍距離は「垂直距離」ではなく、全セグメントに対する**有限線分への最小距離**と書く。

### 第5章　結果

#### 5.1 ルート生成と距離コスト

- system側は15ペアで11件、リルートは1ペア。
- 14/15ペアは距離差0m。
- 横浜→みなとみらいだけ2,277.7mから2,697.6mへ419.9m（18.4%）増えた。
- 18.4%は単一ペアの比率であり、15ペア平均ではない。

#### 5.2 現行Google採点

- oneway 12、two-step 2、合計14、違反ゼロ5/15ペア。
- 件数をGoogleの意図・内部アルゴリズムの主張へ外挿しない。

#### 5.3 曖昧性の三段構え

2.0mを保守的運用値としたとき、次の3段階を同じ表で示す。

| 段階 | 値 | 意味 | 出典 |
|---|---:|---|---|
| 幾何的に曖昧 | 188/379 = 49.60% | 第1・第2候補の距離差が2m未満 | `分析_判定影響曖昧率.md` 13行 |
| 判定内容が変わる | 150/379 = 39.58% | 判定区分・oneway生値・方向・除外タグのtupleが変わる | 同ノート14行 |

補助値として意味正規化後149/379=39.31%を示す。Layer 2は3/23=13.04%である。49.60%だけを「違反判定が不安定」と呼ぶことも、3.17%だけで候補属性の不安定性を隠すことも避ける。

### 第6章　3つの系統的限界

#### 6.1 限界1：外部データの規制例外欠落

- 旧A群6事例は現地で「自転車を除く」補助標識を確認した日本の合法contraflowである。
- 現行で4事例を検出、2事例を非検出。
- 16 historical wayは6/4から8/1にversion・対象タグ・node列の変更が0で、A群2事例もタグ更新ではなくマッチ先変更で非検出になった。

したがって、バッチ7指示書D-5の仮説「OSMコミュニティのタグ更新で解決した」は、既存証拠では**支持されない**。限界1は依然として、正しい規制例外がOSMに表現されない限りアルゴリズム単独で解決できない。ただし、将来コミュニティ編集で解消しうる一般可能性まで否定はできない。また、変更後のマッチ先が法的に正しいwayかは別問題である。

#### 6.2 限界2：way対応の誤り

- 旧B群7事例・8点のうち、現行で5事例・6点が非検出になった。
- 2事例・2点（741785139、1429406683）は残存した。
- よって「7件をすべて解消」「実装修正で解消済み」は削除する。

残存2事例は、有限線分距離に直しても距離最小の候補が正しい道路とは限らないことを示す。ただし、その2事例が限界3と同じ「僅差性」によるかは未確定であり、構造の個別確認前に因果接続を断定しない。

#### 6.3 限界2の変種：道路でない第1候補

- 379点中40点（10.55%）で、診断規則上、自転車通行可能と判定されないwayが第1候補。
- 現行12検出との重複は0、旧18位置とは1点重複。
- 単純フィルタ後に道路候補が44.416m離れる例がある。

「判定入力のway種別に問題があるが、今回の現行違反カウントには直結しなかった」と記す。単純フィルタを解決策として提案しない。7/30旧診断の最大125.4mは別条件なので、現行44.416mと混ぜない。

#### 6.4 限界3：候補僅差による結論不安定性

三段構えの値を中心に据える。原因を「都市部道路網の幾何的構造そのもの」と断定するのではなく、**本データでは近接・交差・接続する別wayが候補競合し、局所距離だけでは対応を一意に決められない**とする。150点の道路関係別分類が未完了なので、構造別の内訳は今後の課題である。

### 第7章　閾値と測定限界

1. 方法論上の主たる閾値候補を1.5mとする。Google encoded polylineの量子化が候補距離差へ与える最悪影響1.437mの直上だからである。
2. 2.0mは、偽の違反断定を避ける損失を重く見た保守的運用値とする。
3. 1.5/2.0/2.5mの感度を併記する。幾何的曖昧は41.16/49.60/56.99%、判定影響は33.51/39.58/45.65%、違反反転は1.58/3.17/4.22%。
4. d1分布から閾値を正当化しない。

### 第8章　法規遵守と安全性

- Layer 1は非免除の一方通行規制に限る。
- 日本のA群6事例は合法contraflowであり、除外すべきでない。
- 欧州の設計・標示された合法contraflowで事故増がみられない研究は、「逆方向は常に危険」という一般化への反証である。
- その結果を日本の無標示・非免除道路へ外挿しない。安全性は道路設計・交差点条件に依存する。

## 2. d1中央値0.781mについて成立する論証と成立しない論証

### 成立する

固定PBFで再構成した候補集合に対し、各Google判定点から**選ばれた最近傍OSM way**までの距離d1は中央値0.781mだった。margin 10m以上の38点でも中央値0.653mであり、「最近傍候補までの距離が一律に数mずれている」という仮説は支持されない。

### 成立しない

「GoogleとOSMの道路形状はサブメートル精度で一致する」「小マージンはデータずれではなく実際の2道路近接だけが原因」「限界3はデータ品質ではなく都市道路構造だけに由来する」は、現在のd1からは言えない。

理由は次のとおり。

- d1は正解wayへの距離ではなく、候補集合の**最小値**であり、選択による下方バイアスがある。
- 違反反転12点を含め正解wayラベルが未確定である。
- Google点は1e-5度に量子化され、最大変位0.718mはd1中央値と同程度である。
- 2つの道路ネットワーク形状を対応付けて差を測ったのではなく、点から任意の最近傍wayを測っただけである。
- 150点の道路関係別分類が未完了で、近接平行・交差・連続分割・重複wayの構成比が分からない。

このため、d1は「大規模な一様オフセットを支持しない」補助結果として使い、限界3の原因を単一に確定する証拠にはしない。
